inlinestaticnoexcept

Single-element activation derivative computed FROM AN ALREADY-ACTIVATED value (e.g. sig*(1-sig) given sig, not given the pre-activation z), the closed-form shortcut every family except GELU supports. Mirrors each family's own dXxx(buf, n, activated=true) in-place formula.

Warning

To keep this dispatcher a drop-in for existing activated=true call sites (which already silently produce a wrong answer for GELU today), the dGELU case here reproduces that same existing behavior, treating activated as if it were raw z, rather than silently changing it. Any layer wanting a correct GELU derivative here needs to be restructured to keep the pre-activation value around separately; that's a real, separate piece of work, not something this dispatcher can paper over.
Parameters

activatedThe already-activated value (or, for dGELU only, see the warning above, the raw pre-activation value).

Attempts C = A @ B(^T) via libxsmm's JIT-dispatched small-GEMM kernel (row-major, same calling convention as CPUBackend::MatMul()). Returns false if libxsmm can't dispatch a kernel for this shape (the caller falls back to MatMul()) – notably, libxsmm's kernels bake alpha=1 in at dispatch time, so this always returns false for any other alpha; callers needing alpha!=1 should try oneDNN first.

Parameters
transA/transB/M/N/K/A/lda/B/ldb/C/ldcSame meaning and shapes as MatMul(). Alpha=1 and beta=0 are implied.
biasWhen non-null, a length-N vector broadcast-added to every row of C (same convention as AddBiasBroadcast), fused into the SAME per-row-block parallel loop that computes that block's GEMM output – not a separate pass. libxsmm has no bias epilogue of its own, unlike oneDNN's fused path; doing the add as its own AddBiasBroadcast() call afterward would need a second OpenMP region and a second full memory pass over C, which measurably regressed the mu GEMM call site (bias add dominates far less than the GEMM itself, but a second pass + region-entry overhead was still enough to erase libxsmm's GEMM win there).
