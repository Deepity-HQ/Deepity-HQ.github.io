Tensor.h		A device-aware, RAII-managed buffer. Device is fixed at construction, there is no support for moving a live Tensor between CPU and GPU after creation. Loading weights saved on CPU and running them on GPU doesn't need that: read the saved file into a plain std::vector on the host, then construct a DEVICE_GPU Tensor directly from that vector (see the host-data constructors below), the one-time host-to-device copy happens inside the constructor, and the temporary host vector falls out of scope immediately after. The Tensor itself is a GPU object from the moment it's born

ModelIO.h		Saves/loads a network's compiled weight arena to/from disk, as a JSON header (per-layer shapes/offsets/dtypes) plus a raw binary data blob. Templated on NetworkType the same as before (works across every PC network variant that exposes GetLayers()), but the element type backing each tensor is no longer assumed to be float: Save() derives it from each tensor's own .data pointer (via DTypeTag<T>), so a FullPCNetworkT<double, ...> writes real "F64" tensors at their real 8-byte stride, not truncated through float. Optimize.h		Defines useful optimization functions of a PC model
    
Profile.h		Per-layer, phase-level timing accumulator, keyed by layer pointer so each layer's phase breakdown (forward GEMM, feedback GEMM, etc.) is reported separately. calculateStateTotal/updateStateTotal are independent top-level timers wrapping the whole call, used to cross-check the sub-phase timers against each other and against an externally-measured wall-clock duration (see PrintAllProfiles())
    
QuantFormat.h		Sub-8-bit storage types for the quantization plan's Phase 2+: each format is its own 1-byte struct (no bit-packing yet, see the plan's own "Known, accepted catch" section), with a free Decode/Encode pair using the paper's grid table. RandomizeDistribution.h		Shared "name(a,b)" distribution-string parser for every PC layer's RandomizeWeights(rng, distribution) overload, generalizing the parsing SimplePCLayer::RandomizeWeights() originally did inline. CPUBackendLibxsmm.h		Declares the libxsmm-backed small-matrix GEMM used by CPUBackend::TryFusedMatMul(). Deliberately a separate CMake target (DeepityLibxsmm, see CMakeLists.txt) that never links or sees MKL: libxsmm's CMake build (unlike its GNU Make build) hardcodes its generated config to LP64 (32-bit libxsmm_blasint) with no way to request ILP64 through this build path, and libxsmm_typedefs.h refuses to compile at all if it sees MKL_ILP64 defined alongside that (a defensive check against actually calling into an ILP64 BLAS through libxsmm's own BLAS-wrapper layer, which this file never does). Rather than downgrade the whole project off MKL_ILP64 to accommodate that, this translation unit is kept out of MKL_ILP64's reach entirely, the same way CPUBackendHighway.cpp is kept out of the project's pinned -march flag
