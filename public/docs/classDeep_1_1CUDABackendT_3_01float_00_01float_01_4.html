 Same operation as MatMul(), but writes into an AccumT* buffer instead of T* – for a layer's own Adam/AdamW gradient computation (grad_W, grad_Psi, ...), which must land in the wider AccumT accumulator, not get rounded down to storage precision T mid-computation (exactly the gap this method closes: MatMul() itself can only ever write a T* C, so it alone can't produce a loss-free gradient when T is a lossy storage format with AccumT != T, e.g. Fp4E2M1Value). void MatMulAccumMixed (bool transA, bool transB, int M, int N, int K, float alpha, const float *A, int lda, const float *B, int ldb, float beta, float *C, int ldc) noexcept override
 Same operation as MatMulAccum(), but A is already AccumT* – for a layer's transient settling/gradient scratch (e.g. the activation-derivative-weighted error signal that feeds both UpdateState()'s feedback GEMM and UpdateWeights()'s gradient GEMM), which must never round-trip through storage precision T even transiently: for a lossy T (e.g. Fp4E2M1Value), an activation derivative's natural range commonly falls entirely below T's coarsest resolution (sigmoid's derivative maxes out at 0.25, below Fp4E2M1Value's smallest nonzero magnitude of 0.5), so writing it into a T* buffer even once rounds it to exactly zero and kills the gradient outright – this is that fix. Only B (the real, stored parameter, e.g. W) decodes from T; A is used as-is.

void Im2Col (const float *input, int batchSize, int channels, int height, int width, int kernelH, int kernelW, int strideH, int strideW, int padH, int padW, float *columns) noexcept override
 Rearranges a whole batch of (channels, height, width) input images into (channels*kH*kW, outH*outW) column matrices, the standard im2col transform, in one call. input is [batchSize, channels, height, width] and columns is [batchSize, channels*kH*kW, outH*outW], both contiguous and batch-major (the layout RepackForBatchedGemm() already expects). On CPUBackend this is a thin loop over Deep::Im2Col() (which genuinely only knows how to do one image at a time); on CUDABackend it's one kernel launch for the whole batch instead of batchSize separate launches – the whole reason this takes a batch dimension at all rather than mirroring Deep::Im2Col()'s single-image contract.  Convolutional bias-add: buf[c*spatialSize + s] += bias[c] for all c in [0,channels), s in [0,spatialSize). Per-CHANNEL broadcast across spatial positions, the transpose relationship to AddBiasBroadcast (which broadcasts a per-COLUMN bias across ROWS, the dense-layer convention).  Convolutional bias-add for the batch-MAJOR NCHW layout: buf[b*channels*spatialSize + c*spatialSize + s] += bias[c] for all b in [0,batchSize), c in [0,channels), s in [0,spatialSize). NOT the same contract as AddBiasPerChannel() above (which needs channel as the OUTERMOST dimension, i.e. [channels, batchSize* spatialSize] – correct for lgRepacked's layout, wrong for mu's). This is what TryFusedConvForward()'s own [batchSize, outChannels, outH, outW] output actually needs: that layout keeps batch outermost, so AddBiasPerChannel() with spatialSize folded to batchSize*trueSpatialSize silently adds bias[c] to the wrong elements whenever batchSize > 1 (confirmed: every gradient-check test in this codebase uses batchSize=1, which collapses the two layouts into the same thing and could never have caught this).
float ComputePrecisionWeightedErrorAndEnergy (float *e, const float *z, const float *mu, const float *p, size_t batchSize, size_t width) noexcept override
 Precision-weighted counterpart to ComputeErrorAndEnergy(): e[b*width+i] = z[b*width+i] - mu[b*width+i] for every b in [0,batchSize), i in [0,width); returns sum_{b,i}(0.5*p'[i]*e^2 - 0.5*log(p'[i])), where p'[i] = max(p[i], 1e-8) (the same floor DiscriminativePCLayer/ConvPCLayer's existing CPU code already applies, guarding against log(0)). p has length width, one precision per own-position, broadcast across every batch item, NOT length batchSize*width like e/z/mu.
void ComputePrecisionWeightedError (float *e, const float *z, const float *mu, const float *p, size_t batchSize, size_t width) noexcept override
 Same as ComputePrecisionWeightedErrorAndEnergy(), without computing (or returning) the energy, for callers that only need e. On CUDABackend this additionally means: no blocking cudaStreamSynchronize() – the ...AndEnergy() variant must synchronously read the energy reduction back to a host value, which is illegal while a CUDA graph is being captured, exactly why this counterpart exists (mirrors ComputeError() alongside ComputeErrorAndEnergy() above).

void UpdatePrecisionFromError (float *p, float *log_p, const float *e, size_t batchSize, size_t width, float pr) noexcept override
 Precision update from accumulated squared error, fused: for each i in [0,width), grad = mean_{b in [0,batchSize)} of 0.5*(p[i]*e[b*width+i]^2 - 1); log_p[i] -= pr*grad, clamped to [-5,5]; p[i] = exp(log_p[i]). Matches DiscriminativePCLayer::UpdatePrecision()/ConvPCLayer::UpdatePrecision()'s existing CPU formula exactly, including the clamp bounds.
