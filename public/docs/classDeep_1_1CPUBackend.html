 Same operation as MatMul(), but writes into an AccumT* buffer instead of T* – for a layer's own Adam/AdamW gradient computation (grad_W, grad_Psi, ...), which must land in the wider AccumT accumulator, not get rounded down to storage precision T mid-computation (exactly the gap this method closes: MatMul() itself can only ever write a T* C, so it alone can't produce a loss-free gradient when T is a lossy storage format with AccumT != T, e.g. Fp4E2M1Value). void MatMulAccumMixed (bool transA, bool transB, int M, int N, int K, float alpha, const float *A, int lda, const float *B, int ldb, float beta, float *C, int ldc) noexcept override
 Same operation as MatMulAccum(), but A is already AccumT* – for a layer's transient settling/gradient scratch (e.g. the activation-derivative-weighted error signal that feeds both UpdateState()'s feedback GEMM and UpdateWeights()'s gradient GEMM), which must never round-trip through storage precision T even transiently: for a lossy T (e.g. Fp4E2M1Value), an activation derivative's natural range commonly falls entirely below T's coarsest resolution (sigmoid's derivative maxes out at 0.25, below Fp4E2M1Value's smallest nonzero magnitude of 0.5), so writing it into a T* buffer even once rounds it to exactly zero and kills the gradient outright – this is that fix. Only B (the real, stored parameter, e.g. W) decodes from T; A is used as-is.
void SetAllowTF32 (bool) noexcept override
 Whether MatMul() may use TF32 (10 mantissa bits, ~1e-3 relative error per GEMM) instead of full FP32 on tensor cores – CUDABackend only; a no-op on CPUBackend, which has no such distinction. Defaults to allowed, matching PyTorch's own default, since every conv in this library lowers to im2col+MatMul and would otherwise run at a fraction of the GPU's peak throughput. Turn off before a finite-difference gradient check: TF32's error is large enough to either fail those checks for no real reason, or tempt loosening their tolerance until it stops catching real bugs.

bool TryFusedFeedbackUpdate (ActivationType dType, int batchSize, int size, int nextSize, const float *eAbove, const float *W, float *z, const float *e, float ir, float *scratch, float *derivScratch) noexcept override
 Fuses SimplePCLayer::UpdateState()'s feedback GEMM directly into its own elementwise state update – the GEMM's output is never separately read back and re-walked by its own pass: feedback = e_above @ W (M=batchSize,N=size,K=nextSize) z += ir * (f'(z) * feedback - e) Primary mechanism (CPUBackend, DEEPITY_USE_ONEDNN): a dnnl::matmul primitive with the elementwise update welded on as post-ops (binary_mul/binary_add), evaluated in registers on each output tile right as oneDNN's own GEMM microkernel produces it – same kernel, same thread pool as every other matmul in this file, just with the epilogue attached. Works for every ActivationType oneDNN can be handed a precomputed derivative for (i.e. all of them, via ActivationDerivativeInto()), unlike the Halide fallback below. Secondary fallback (DEEPITY_USE_HALIDE only, off by default): an ahead-of-time Halide kernel (src/backend/halide/ FeedbackUpdateGenerator.cpp) that was this project's first attempt at this fusion – kept only because it's verified correct, not because it's fast: measured slower than oneDNN's separate GEMM+elementwise pair even after a properly-tiled schedule, because its own thread pool oversubscribes CPU cores alongside oneDNN's (see DEEPITY_USE_HALIDE's CMakeLists.txt comment for the full writeup). Only ActivationType::SIGMOID and nextSize>=64 reach it. Any dType neither path handles, or every path failing/disabled, returns false so the caller falls back to its own separate TryFusedMatMul()/ FusedStateUpdate() calls, same convention as TryFusedMatMul() above.

 Fuses ComputeError()'s e = z - mu with the forward activation zF = f(z) that SimplePCLayer::ComputeMuOnly() computes right afterward in the common (non-cross-entropy, no-energy-needed) settling step – both read the same z, so this halves that read and pays one OpenMP fork/join instead of two, see SimplePCLayer::CalculateState()'s call site for the exact condition under which this applies instead of the separate ComputeError()/ ActivationInto() pair. float ComputeSoftmaxCrossEntropyErrorAndEnergy (float *e, const float *z, const float *mu, size_t batchSize, size_t nextSize, float *rowEnergies) noexcept override
 Softmax cross-entropy variant of ComputeErrorAndEnergy, for the terminal layer only. Unlike the Gaussian version, this needs batchSize/nextSize separately (not just a flat n) since softmax is a row-wise, not element-wise, operation. probs = softmax(mu), row-wise e = z - probs (z is the clamped target; matches the existing e := -dF/dmu convention exactly, since d(CE)/d(logits) = probs - y) energy = -sum(z * log(probs + eps)) (eps=1e-8, avoids log(0)) mu holds the RAW LOGITS (unchanged from the Gaussian case, still a*W@phi(z)+b), softmax is applied here, not baked into mu itself. rowEnergies is caller-provided scratch, >= batchSize elements, NOT allocated internally (this runs inside CalculateState(), which runs inside TrainStep()'s CUDA-graph-captured region; dynamic allocation there is unsafe under capture, same reasoning as the CUTLASS workspace). CPUBackend's own override ignores this parameter entirely, kept in the shared interface so callers pass the same arguments to either backend.

void Im2Col (const float *input, int batchSize, int channels, int height, int width, int kernelH, int kernelW, int strideH, int strideW, int padH, int padW, float *columns) noexcept override
 Rearranges a whole batch of (channels, height, width) input images into (channels*kH*kW, outH*outW) column matrices, the standard im2col transform, in one call. input is [batchSize, channels, height, width] and columns is [batchSize, channels*kH*kW, outH*outW], both contiguous and batch-major (the layout RepackForBatchedGemm() already expects). On CPUBackend this is a thin loop over Deep::Im2Col() (which genuinely only knows how to do one image at a time); on CUDABackend it's one kernel launch for the whole batch instead of batchSize separate launches – the whole reason this takes a batch dimension at all rather than mirroring Deep::Im2Col()'s single-image contract. Positions outside the input (due to padding) are written as zero. columns is fully overwritten, not accumulated into.

void RepackForBatchedGemm (float *dst, const float *src, size_t batchSize, size_t rows, size_t cols) noexcept override
 Repacks a [batchSize, rows, cols] tensor (batch-major) into [rows, batchSize, cols] (row-major, batch second), i.e. dst[row][batch][col] = src[batch][row][col] for all row/batch/col, with the innermost cols dimension kept contiguous on both sides. Used by ConvPCLayer-family layers to reorganize per-batch im2col columns (and per-batch upstream-error columns) into the single flat layout a plain (non-batched) GEMM call needs, rather than one GEMM call per batch item. Same "port first, optimize" position as AddBiasBroadcast/SumRows: a future strided-batched-GEMM path could remove the need for this entirely, but this matches the existing, verified CPU repacking loops exactly for now.
bool TryFusedConvForward (const float *, const float *, float *, float, int, int, int, int, int, int, int, int, int, int, int) noexcept override
 Attempts a single fused convolution forward pass, skipping Im2Col()/RepackForBatchedGemm()/MatMul() entirely: output = alpha * conv(input, W), in the same [batchSize, outChannels, outH, outW] NCHW layout the Im2Col()+RepackForBatchedGemm()+MatMul() fallback's own un-repack produces. void AddBiasPerChannel (float *buf, const float *bias, size_t channels, size_t spatialSize) noexcept override
 Convolutional bias-add: buf[c*spatialSize + s] += bias[c] for all c in [0,channels), s in [0,spatialSize). Per-CHANNEL broadcast across spatial positions, the transpose relationship to AddBiasBroadcast (which broadcasts a per-COLUMN bias across ROWS, the dense-layer convention).
