 Google Highway (github.com/google/highway) runtime-dispatched implementations for several CPUBackend elementwise kernels that were previously plain scalar loops: AddBiasPerChannel, Fill, MultiplyInto, and (for a subset of ActivationType, see below) FusedActivationDerivativeMultiply, FusedStateUpdate and FusedStateUpdateMomentum.  		CPUBackendHighway.h
 Declares the Google Highway (github.com/google/highway) runtime- dispatched implementations backing a handful of CPUBackend's elementwise kernels. Deliberately a separate CMake target (DeepityHighwayKernels, see CMakeLists.txt) compiled WITHOUT the project's hard-pinned -march flag – Highway's own foreach_target.h mechanism compiles multiple per-ISA-target variants of CPUBackendHighway.cpp and picks the best one at runtime; a project-wide fixed ISA would defeat that entirely.
 		CPUBackendLibxsmm.cpp
 		CPUBackendLibxsmm.h
 Declares the libxsmm-backed small-matrix GEMM used by CPUBackend::TryFusedMatMul(). Deliberately a separate CMake target (DeepityLibxsmm, see CMakeLists.txt) that never links or sees MKL: libxsmm's CMake build (unlike its GNU Make build) hardcodes its generated config to LP64 (32-bit libxsmm_blasint) with no way to request ILP64 through this build path, and libxsmm_typedefs.h refuses to compile at all if it sees MKL_ILP64 defined alongside that (a defensive check against actually calling into an ILP64 BLAS through libxsmm's own BLAS-wrapper layer, which this file never does). Rather than downgrade the whole project off MKL_ILP64 to accommodate that, this translation unit is kept out of MKL_ILP64's reach entirely, the same way CPUBackendHighway.cpp is kept out of the project's pinned -march flag.
